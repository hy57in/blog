# 블로그 글 리뷰 스킬

블로그 포스트를 리뷰하여 개선점을 제안합니다. 작성자의 문체 패턴과 한국 기술 블로그 공통 패턴을 기반으로 검토합니다.

## 사용법

리뷰할 MDX 파일 경로를 인자로 전달합니다: `/review-blog posts/파일명.mdx`

## 리뷰 절차

1. 대상 MDX 파일을 읽는다
2. 아래 체크리스트 항목별로 검토한다
3. 항목별 통과(O) / 개선필요(X) / 해당없음(-)으로 표시하고, 개선이 필요한 항목에 구체적 제안을 덧붙인다

## 리뷰 체크리스트

### A. 구조 (Structure)

- [ ] **도입부**: 첫 문장에서 바로 상황/배경을 제시하는가? (장황한 인사 없이)
- [ ] **문제 인식**: 도입부에서 "왜 이 글을 쓰게 되었는지" 동기가 명확한가?
- [ ] **본문 흐름**: 문제 → 시도 → (실패/교훈) → 해결 서사 구조를 따르는가?
- [ ] **섹션 번호**: `##` heading에 번호가 매겨져 있다면 순서가 자연스러운가?
- [ ] **마무리**: `## 마치며` 또는 `## 마무리하며`로 회고와 소감을 담고 있는가?
- [ ] **끝 인사**: "긴 글 읽어주셔서 감사합니다!"가 있는가? (기술 글일 경우)
- [ ] **참고 자료**: 외부 링크가 있다면 `## 참고 자료` 섹션으로 분리했는가?
- [ ] **구분선**: `---` 구분선을 남용하지 않았는가? (frontmatter 제외)

### B. 문체 (Writing Style)

- [ ] **일관된 문체**: 글 전체에서 합쇼체("~습니다") 또는 해라체("~이다")가 혼용 없이 일관적인가?
  - 기술 글/경험 공유 → 합쇼체
  - 강연 노트/에세이 → 해라체
- [ ] **구어체 밸런스**: 적절한 곳에 구어체를 섞어 딱딱함을 줄이고 있는가? (예: "이거 React랑 구조가 똑같잖아?")
- [ ] **과도한 수식어**: 불필요하게 장황한 수식어나 미사여구가 없는가?
- [ ] **사실 정확성**: 경험담에서 과장이나 사실과 다른 표현이 없는가? ("이틀을 날렸다" 같은 과장)

### C. 임팩트 표현 (Impact & Evidence)

- [ ] **숫자로 증명**: 성과나 규모를 구체적 숫자로 제시하는가? (예: "90% 단축", "1,700개 화면")
- [ ] **Before/After**: 도입 전후 비교가 있는가? (코드, 수치, 프로세스)
- [ ] **볼드 강조**: 핵심 키워드나 인사이트에 **볼드** 처리가 되어 있는가? (과도하지 않게)
- [ ] **직접 인용**: 팀원 반응이나 본인 생각을 따옴표로 생동감 있게 표현하는가?

### D. 콘텐츠 품질 (Content Quality)

- [ ] **대상 독자**: 글이 누구를 위한 것인지 명확한가? ("이 글은 이런 분들께 도움이 됩니다" 등)
- [ ] **교훈 공유**: 실패나 어려움을 솔직하게 공유하고, 거기서 얻은 교훈을 제시하는가?
- [ ] **트러블슈팅**: 겪은 문제와 해결 과정이 구체적인가?
- [ ] **실용성**: 독자가 바로 적용할 수 있는 구체적 정보(코드, 설정, 명령어)가 있는가?
- [ ] **비유/메타포**: 복잡한 개념을 쉽게 설명하는 비유가 적절히 사용되었는가?

### E. Frontmatter & SEO

- [ ] **제목**: 숫자나 구체적 키워드가 포함된 제목인가? (예: "90% 단축", "1,700개 화면")
- [ ] **summary**: 글의 핵심을 1-2문장으로 요약하고 있는가?
- [ ] **publishedAt**: 날짜가 올바른 형식(YYYY-MM-DD)인가?

### F. 기술 블로그 공통 패턴 (Korean Tech Blog Best Practices)

- [ ] **네러티브**: 단순 나열이 아닌, 스토리텔링 구조로 되어 있는가?
- [ ] **솔직함**: 실패 사례를 숨기지 않고 공유하는가? (채널톡, 토스 스타일)
- [ ] **팀 기여**: 도움 준 동료나 팀에 대한 감사가 자연스럽게 녹아 있는가?
- [ ] **후속 과제**: "앞으로 남은 과제" 등 향후 계획을 제시하여 연속성을 보여주는가?
- [ ] **코드 블록**: 코드 예시가 있다면 적절한 주석과 함께 핵심만 보여주는가? (전체 코드 X)

## 리뷰 출력 형식

```
## 블로그 리뷰 결과: {제목}

### 총평
(2-3줄로 전체 인상)

### 체크리스트 결과
| 영역 | 통과 | 개선필요 | 해당없음 |
|------|------|----------|----------|
| A. 구조 | X개 | X개 | X개 |
| B. 문체 | X개 | X개 | X개 |
| ... | ... | ... | ... |

### 개선 제안
(개선필요 항목별로 구체적 제안. 가능하면 수정 전/후 예시 포함)

### 잘 된 점
(특히 잘 된 2-3가지)
```

## 참고: 작성자 문체 특성

- 기술 글은 **합쇼체** ("~습니다"), 에세이/강연 노트는 **해라체** ("~이다")
- 도입부에서 바로 상황 제시, 문제 인식으로 빠르게 진입
- **볼드** 키워드 강조를 적극 활용
- 구어체를 적절히 섞어 딱딱함을 완화 ("이거 자동화할 수 없을까?")
- 숫자로 임팩트 증명 (90%, 4,300 M/D, 202개)
- 마무리에 솔직한 회고 + 개인적 소감 + "긴 글 읽어주셔서 감사합니다!"
- Before/After 비교와 POC/가설 검증 접근 선호
